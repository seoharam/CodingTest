# CodingTest

기업 코딩테스트 대비용 알고리즘 연습 저장소.

## 구조 규칙

- 문제 하나당 파이썬 파일 하나 (`알고리즘명.py`)
- 각 파일은 `problems/` 폴더의 이미지와 1:1로 매칭됨, 파일명은 `알고리즘명_example.png`
  - 예: [BFS.py](BFS.py) ↔ [problems/BFS_example.png](problems/BFS_example.png)
- 코드 상단에는 개념 정리 + 문제 분석을 주석으로, 코드 본문에는 각 줄 우측에 한 줄 설명 주석을 단다

`BFS.py`가 이 구조의 베이스 템플릿이다.

## 알고리즘 선택 가이드

| 구분 | **BFS** | **DFS** | **백트래킹 (Backtracking)** |
|---|---|---|---|
| 핵심 자료구조 | 큐 (Queue, FIFO) | 재귀 / 콜 스택 (LIFO) | 재귀 / 콜 스택 (LIFO) + 상태 되돌리기 |
| 탐색 방식 | 가까운 것부터 계층별로 | 한 방향으로 끝까지 파고듦 | DFS처럼 파고들되, 조건 안 맞으면 즉시 후퇴 |
| 방문 체크(chk) | 한 번 방문하면 영구 유지 | 한 번 방문하면 영구 유지 | 방문 → 되돌리기(`=False`) 반복 |
| 정답 개수 | 보통 1개 (최단거리 등) | 보통 1개 (연결요소 개수 등) | 보통 여러 개 (모든 조합/경우의 수) |
| Pruning | 없음 (경계/중복 체크만) | 없음 (경계/중복 체크만) | 있음 (답이 될 수 없는 방향은 아예 진입 안 함) |
| 예시 파일 | [BFS.py](BFS.py) — 그림 개수·최대 크기 | [DFS.py](DFS.py) — 그림 개수·최대 크기 (BFS와 결과 동일) | [BackTracking.py](BackTracking.py) — N개 중 M개 뽑는 모든 순열 |

### 언제 어떤 걸 써야 하는지

**BFS를 써야 할 때**
- "최단 거리/최소 횟수"가 필요할 때 → 계층별로 퍼지는 구조라 처음 도달한 순간이 곧 최단 경로임이 보장됨
- 예: 미로 최단 경로, 친구 관계에서 몇 단계 만에 연결되는지

**DFS를 써야 할 때**
- 거리는 상관없고, "연결되어 있는지/개수"만 필요할 때
- 재귀 깊이가 너무 깊어질 위험이 없는(격자가 과도하게 크지 않은) 경우에 특히 편함
- 예: 섬 개수 세기, 사이클 존재 여부 확인, 위상 정렬

**백트래킹을 써야 할 때**
- "가능한 모든 후보(조합/순열/배치)"를 찾아야 하고, 그중 조건을 만족하는 것만 골라야 할 때
- 완전탐색은 해야 하는데, 특정 조건 때문에 대부분의 경우는 답이 될 수 없다는 게 미리 판단 가능해서 가지치기로 탐색 범위를 줄일 수 있을 때
- 예: N-Queen, 순열/조합 생성, 스도쿠, 부분집합의 합

**한 줄 요약**
- "몇 걸음 만에 도착하는가?" → BFS
- "연결되어 있는가/개수는?" → DFS
- "조건을 만족하는 모든 배치를 찾아라" → 백트래킹

## 알고리즘 선택 가이드 (2)

| 구분 | **시뮬레이션 (Simulation)** | **투 포인터 (Two Pointers)** | **이진탐색 (Binary Search)** | **그리디 (Greedy)** |
|---|---|---|---|---|
| 핵심 아이디어 | 문제에 적힌 조건/규칙을 그대로 구현 | 두 포인터(커서)를 움직이며 구간을 관리 | 정렬된 범위를 절반씩 좁혀나감 | 매 순간 가장 좋아 보이는 선택을 반복 |
| 요구 조건 | 없음 (구현력이 핵심) | 데이터가 "연속 구간" 성질을 가짐 | 탐색 대상에 단조성(정렬)이 있어야 함 | 각 단계의 선택이 전체 최적해를 해치지 않는다는 증명 필요 |
| 시간복잡도 | 문제별 규칙에 따라 다름 | O(N) | O(log N) | 보통 O(N) ~ O(N log N) |
| 예시 파일 | [Simulation.py](Simulation.py) — 로봇청소기 이동 시뮬레이션 | [TwoPointers.py](TwoPointers.py) — 연속 K일 구간합 최댓값 | [BinarySearch.py](BinarySearch.py) — 정렬된 배열에서 원소 존재 여부 확인 | [GreedySearch.py](GreedySearch.py) — 동전 개수 최솟값 |

### 언제 어떤 걸 써야 하는지

**시뮬레이션을 써야 할 때**
- 별도의 알고리즘 이론보다, 문제에 적힌 규칙(이동/회전/조건 분기)을 순서대로 그대로 코드로 옮기는 구현력이 핵심일 때
- 예: 로봇 청소기, 뱀 게임, 격자 위 이동/회전

**투 포인터를 써야 할 때**
- 배열/리스트에서 "연속된 구간"의 합이나 조건을 반복 확인해야 하고, 매번 처음부터 다시 계산하지 않고 이전 구간의 계산 결과를 재활용할 수 있을 때
- 예: 연속 부분합의 최댓값, 두 수의 합이 특정 값이 되는 구간 찾기

**이진탐색을 써야 할 때**
- 정렬된 데이터에서 특정 값의 존재 여부/위치를 빠르게 찾아야 할 때
- "정답이 될 수 있는 값의 범위"가 단조성을 가져서, 값 하나를 정하고 "이 값이 조건을 만족하는가?"를 판별해가며 범위를 좁혀나갈 수 있을 때 (파라메트릭 서치)
- 예: 정렬된 배열에서 수 찾기, 최적화 문제의 정답을 이분탐색으로 탐색

**그리디를 써야 할 때**
- 매 순간 최선의 선택을 반복해도 전체 최적해가 보장된다는 것을 증명(또는 반례가 없음을 확인)할 수 있을 때
- 예: 동전 개수 최소화, 회의실 배정

**한 줄 요약**
- "규칙을 그대로 구현해라" → 시뮬레이션
- "연속 구간을 효율적으로 훑어라" → 투 포인터
- "정렬된 곳에서 빠르게 찾아라" → 이진탐색
- "매 순간 최선을 선택해도 되는가?" → 그리디
